# Supported transfer and offboarding scope

This release supports one company per deployment with a single backend process and
durable PostgreSQL/private artifact storage. Public community reading remains public;
this is not a private-community access-control release.

## Implemented and verified

- **Company/native migration:** snapshot-consistent company export, protected ZIP
  download, quarantined inspection, private dry run, bounded atomic activation into
  an empty bootstrap target, and durable reconciliation. Optional contacts and
  moderation history have explicit inclusion rules. Native round-trip, rollback,
  restart and lost-response tests cover the workflow.
- **Personal export:** authenticated requester-only export, independent of role.
  It excludes other people's bodies, private moderator notes and credentials.
  Opaque references can point outside the archive. Personal archives cannot be imported.
- **External adapter:** the versioned CommonBeacon bundle generated by the documented
  Discourse **3.5.0** helper. Supported mappings and acknowledged losses are specified
  in the [adapter guide](discourse-import.md). No compatibility claim applies to
  other Discourse versions, raw backups, plugins or unlisted entities.
- **Deletion/offboarding:** confirmed account pseudonymization and opt-in company
  erasure, artifact cleanup, receipts and an erasure-ledger restore procedure.
  [Offboarding](offboarding.md) defines retained public content, backups, deadlines
  and operator obligations. Erasure is distinct from export and normal job retention.

## Explicitly outside this release

Higher Logic Thrive, Gainsight, Khoros, Higher Logic Vanilla, Bettermode and Bevy have
no verified adapters. Their names are not selectable providers or format guarantees.
New adapters require representative, authorized source data and verified mappings.

Imported authors preserve attribution only: they are inactive MEMBER identities
without login email or password. Retained contacts prove neither ownership nor
verification. Matching an email or registering later does not claim historical
content. Verified account claiming, invitations, administrator bootstrap, email
verification, password recovery and MFA remain separate identity work.

Populated-target merges, incremental synchronization, arbitrary file uploads,
oversized imports, multi-backend operation and distributed rate limiting are not
supported. Local recovery tests are not production disaster-recovery certification.
Infrastructure capacity, TLS/proxy configuration, secure backups, restore drills,
backup expiry and legal/retention policy still require deployment-specific work.

## Evidence and reproduction

The [migration guide](migration-guide.md) is the operator entry point. The
[verification record](transfer-verification.md) records synthetic local capacity
measurements and crash boundaries, including the 40,000-record supported count limit.
The regression baseline passed 343 backend tests and 172 frontend tests, plus native,
personal, Discourse, erasure, restart and cleanup journeys. This evidence does not
remove the independent byte/time limits or certify a production workload.

The source-only setup check builds the committed runtime from a Git archive with
no `.env`, host dependencies, build output or existing volumes. It disables demo
seeding, checks member registration and denied administrator access, and exercises
personal export/download. Run it with Git, Docker, tar and Node 24 available:

```powershell
node scripts/verify-source-only.mjs
```

It uses a unique temporary Compose project and port 4181, and removes only its own
containers, network, volumes and source copy. It does not provision administrators
or claim to prove production company onboarding. The full import suites use
explicitly test-only administrator fixtures, as documented in
[browser testing](browser-testing.md). Detailed development plans stay untracked.
